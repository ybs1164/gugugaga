# 전체 비주얼의 2D 픽셀 전환 계획

작성일: 2026-10-01. 실행 현황과 검증 결과는 [2D 구현 기록](Pixel2DImplementation.md)에 정리한다. 이 문서의 아래 내용은 최초 계획이며, 구현에서 선택한 방식과 차이는 구현 기록을 기준으로 확인한다.

## 1. 권장 방향과 가능 범위

**정사각형 격자의 탑다운 2D + Kenney Tiny 계열 CC0 픽셀 에셋**을 기본안으로 한다. Tiny Town / Tiny Farm으로 월드와 경제 요소, Tiny Dungeon으로 판타지 보병과 아이콘, UI Pack - Pixel Adventure로 UI를 구성한다. 전투·경제·기술·맵 생성 데이터는 유지하고 표시 계층을 교체한다.

무료 에셋 구매 비용 0원으로 전체 화면을 2D로 바꾸는 것은 가능한 목표다. 다만 현재의 모든 유닛·건물에 정확히 대응하는 완성 스프라이트가 무료 팩 안에 있다는 뜻은 아니다. 기병, 투석기, 6종 함선, 등대, 불가사리, 특수 기념물은 다운로드 후 확인이 필요하며, 없으면 CC0 스프라이트 조합과 소규모 픽셀 수정으로 채운다. 별도 모델 제작은 없애되 스프라이트 편집 작업은 예상한다. 수정 없이 전부 1:1 교체할 수 있다는 약속은 하지 않는다.

현재 로우폴리 외형을 그대로 재현하는 것보다 역할 식별, 칸 판독, 도시 성장 표현을 우선한다. 기존 아이소메트릭 카메라를 유지하면 일반 탑다운 픽셀 팩과 시점이 어긋나므로 기본안에서는 고정 정면 직교 카메라로 전환한다.

## 2. 현재 교체 대상

실제 렌더링은 외부 FBX만으로 구성되지 않는다. CSV 기반 절차적 메시와 런타임 생성 비주얼까지 전환 대상에 포함한다.

| 범주 | 현재 위치·구성 | 2D 대체 방식 |
| --- | --- | --- |
| 지면 | `GridView`, `TileView`, `TerrainModels.csv`; 평지·숲·산·얕은 물·바다 | Ground Tilemap + 숲·산 Sprite, 물 색·해안 연결 타일 |
| 지형 장식 | `TerrainFeatureView`, `ModelBuilder`, 타일 받침 | 나무·바위 Sprite; 높이 표현은 그림 안에서 처리 |
| 미탐험 영역 | `GridView.RefreshFog`, 구름 메시 | Fog Tilemap; 기존 탐험 판정과 숨김 규칙 유지 |
| 구조물·자원 | `StructureDefinition`, `Assets/Prefabs/Structures`, `Assets/Materials/Structure_*` | 수도·마을·유적·과일·작물·사냥감·광물·물고기·등대·불가사리 Sprite; 구 식량/광석 ID도 매핑 |
| 일반 건물 | `Buildings.csv`, `BuildingModels.csv`, `BuildingMarkerView` | 벌목장·농장·광산·항구·제재소·풍차·대장간·시장·신전 4종 |
| 도로·다리 | `Road.Center`, `Road.Arm`, `Building.Bridge` | 인접 4방향 연결 마스크 기반 Tilemap; 다리 가로/세로 이미지 |
| 기념물 | `Buildings.csv`의 7종 | 제단·무덤·눈의 탑·성문·대시장·공원·지혜의 탑을 서로 다른 조합 Sprite로 표현 |
| 도시 성장 | `City.Houses/Capital/Wall/Workshop/Park/Flag` | 단계별 도시 + 성벽·수도·공방·공원·팀 깃발 오버레이 |
| 육상 유닛 | `UnitView`, `UnitDefinition`, `UnitModels.csv`, `Assets/Prefabs/Units` | infantry, shield, gladiator, cavalry, knight, archer, catapult, cleric, spy, dagger, giant 모델 키별 Sprite 매핑; 프리팹·CSV에서 추가 참조 키도 수집 |
| 해상 유닛 | `NavalUnits.csv`, `Boat.*`, `UnitView` 승선 표시 | raft, scout, rammer, bomber, dinghy, pirate별 선체 + 탑승 표시 |
| 외부 모델 | `Assets/Art/KayKit`, `KayKitSkeletons`, `Village`, `Castle`, `Tiles` | 최종 참조 제거 후 빌드 제외·정리 |
| UI | `Assets/Prefabs/UI`, HUD들, `IconLibrary`, `RuntimeSprite` | 픽셀 패널·버튼·바·아이콘; 기존 한국어 텍스트 가독성 유지 |
| 표시 효과 | 선택·이동·공격 범위, 영토 경계, HP, 피해 팝업, 상태·패시브 | 픽셀 오버레이·아이콘·2D 효과; 팀 색 외에 문양/테두리도 사용 |

파일별 이름만 바꾸지 않고 `ModelBuilder.Build`, 메시 생성, 머티리얼 교체, 프리팹 fallback 경로까지 조사한다. 저장소에 남는 원본과 실제 빌드에서 사용하는 자산을 구분한다. 오디오가 존재하면 별도 목록으로 보존하며, 2D 전환 때문에 교체할 필요는 없다.

**Tiny Swords 주의점:** 현재 Free Pack에는 사용·수정 허용과 별도로 재배포·재판매·재포장 금지 조항이 있다. 페이지의 구버전 CC0 다운로드와 최신 Free Pack을 같은 라이선스로 취급하지 않는다. 저장소에 원본을 포함하기 쉬운 CC0 팩을 기본안으로 선정한다.

같은 16×16 계열이라도 시점·외곽선·팔레트가 자동으로 일치하는 것은 아니다. 먼저 한 화면에 섞어 보며 비교하고, 주력 팩을 중심으로 보조 팩의 색과 그림자를 맞춘다. 16×16과 64×64를 한 화면의 기본 재료로 혼용하지 않는다.

## 4. 비주얼 규격

- 기본 원본 격자: 16px. 초기 월드 셀은 16×16px, 큰 도시·기념물·거인은 필요 시 32×32px 캔버스로 구성한다. 셀 바깥으로 나오는 장식이 이웃 칸의 선택 표시를 가리지 않도록 배치한다.
- PPU: 16으로 시작하고 셀 크기와 함께 한 곳에서 관리한다. 유닛·건물은 발밑 pivot, 지면은 셀 중심 기준으로 맞춘다.
- Texture Import: Sprite, Point 필터, mipmap 비활성화, 초기 압축 없음. atlas 패딩·슬라이스 경계를 검사한다.
- 기본 조명은 Unlit. 실제 그림자·3D 조명 대신 스프라이트 내부 음영과 작은 발밑 그림자를 사용한다.
- 정수 배율과 픽셀 스냅을 우선한다. 기준 해상도는 전체 HUD가 들어가는지 확인 후 결정하며 640×360을 첫 검토값으로 사용한다. UI Canvas와 월드의 스케일 정책은 따로 점검한다.
- 정렬: Ground → Road → Shadow → Object/Unit → Range/Selection → Fog → HUD. Object/Unit 내부는 발밑 Y 기준 정렬, 유닛 장비·선체·배지는 SortingGroup 단위로 묶는다.
- 도시와 유닛이 같은 칸에 있을 때 유닛 식별을 우선하고 도시 배지·레벨이 보이는 위치를 확보한다.
- 한국어는 기존 `Jua-Regular.ttf`를 우선 유지한다. 픽셀 폰트 교체는 한글 글리프·작은 크기 가독성이 확인될 때만 진행한다.
- 애니메이션 최소 범위: idle 1프레임, 이동 위치 보간, 공격 짧은 모션, 피격 점멸, 사망 fade. 무료 팩에 방향별 프레임이 없다면 4방향 애니메이션을 전환 완료 조건으로 요구하지 않는다. 픽셀 스냅 이동의 떨림도 확인한다.

## 5. 에셋 매핑과 부족분 처리

`Assets/Art/Pixel2D/ThirdParty/<Author>/<Pack>/`에 원본과 LICENSE를 보관하고, 편집본은 `Assets/Art/Pixel2D/Derived/`에 분리한다. 구매 비용은 0원을 목표로 하며 편집·통합 공수는 별도다.

신규 표시 매핑은 `SpriteCatalog.csv` 또는 순수 데이터 카탈로그로 관리한다. CSV를 사용한다면 한 칸에 한 값으로 `VisualId,Variant,Layer,SpritePath,PixelsPerUnit,PivotX,PivotY,FrameCount,Fps,SourcePack`처럼 펼친다. 조합 이미지의 각 레이어는 별도 행으로 둔다. 실제 선택·로드 함수는 View/로더 계층에 둔다. 기존 게임플레이 ID와 스탯 테이블은 유지하며, 기존 `ModelId`를 새 표시 키로 해석하거나 명시적 호환 매핑을 둔다.

첫 인벤토리는 모델 CSV의 정의 키뿐 아니라 `UnitDefinition`, 런타임 문자열 조합, 구 CSV 호환 ID, UI 행동·패시브·기술 아이콘까지 수집한다. 각 키에 `직접 대체 / 조합·수정 / 미확인` 상태, 출처, 최종 Sprite, 검증 화면을 기록한다. 미매핑 키는 눈에 띄는 2D 임시 표시와 진단 로그로 드러내며 최종 완료 시 0개를 요구한다.

부족분은 다음 순서로 해결한다.

1. 같은 팩에서 역할이 명확한 그림을 선택한다. 원작 실루엣과 일치하지 않아도 병종 역할이 읽히면 사용한다.
2. 무기·방패·깃발·탈것·돛 등의 CC0 파츠로 조합하고 팔레트를 통일한다.
3. 직접 작은 픽셀 수정으로 빈 항목을 채운다. 우선 후보는 기병/기사, 투석기, 6종 함선, 등대·불가사리, 7종 기념물이다.
4. 도시·신전 레벨은 모든 레벨의 별도 그림 대신 기본 그림 + 증축·배지로 표현할 수 있다. 실제 성장 단계의 차이는 확인 가능해야 한다.

함선은 모두 같은 배에 색만 바꾸지 않는다. 돛, 충각, 포, 작은 선체, 검은 돛 등으로 최소한 역할별 실루엣을 구분한다. 기병과 기사는 탈것을 유지하며, giant를 작은 보병과 같은 크기로 대체하지 않는다.

## 6. 코드·씬 전환 설계

1. **좌표와 입력부터 공통화한다.** 현재 `GridWorld.GridToWorld`는 XZ 좌표이고 `BattleController.TryScreenToGridPos`는 XZ 바닥 평면과 ray 교차를 계산한다. 신규 View 좌표 어댑터에서 논리 `(x,y)`를 화면 XY로 변환하고 역변환한다. 기존 데이터를 일괄 수정하기보다 렌더링 호출부를 어댑터로 옮긴다. 중앙 좌표 기준이므로 클릭 경계의 반 칸 offset도 통일한다.
2. **모든 좌표 소비자를 옮긴다.** GridView, UnitView, 카메라 중심·패닝, `FaceTowards`, 배치 미리보기, HP·피해 팝업 앵커, 호버를 포함한다. 임의로 Vector3 축만 바꾸고 끝내지 않는다. UI 위 클릭은 기존처럼 월드 입력에서 제외한다.
3. **지면과 오버레이를 Tilemap으로 옮긴다.** 이동·공격 범위와 영토 경계는 원본 이미지 색을 덮어쓰기보다 별도 표시 레이어로 구성한다. 지형·도로 수정은 변경 칸과 연결 상태가 바뀐 이웃 칸만 갱신한다.
4. **GridView의 메시 경로를 교체한다.** 타일 높이·WaterDrop·StructureLift·받침 메시 의존을 제거하고, feature/structure/building/road/fog를 2D로 생성한다. 자원 소모·건설·벌목 이후 표시가 재등장하지 않도록 기존 숨김 규칙을 이식한다.
5. **UnitView의 표시 기능을 교체한다.** ID 연결·스탯·행동은 유지하고 모델 생성·몸 방향·팀 머티리얼을 Sprite/Animator와 배지로 바꾼다. 승선·하선 때 선체와 탑승 표시를 교체한다. 이동 애니메이션 종료와 실제 위치 판정도 함께 검증한다.
6. **건물·도시 표시를 교체한다.** BuildingMarkerView와 도시 성장 레이어를 이식한다. `ModelBuilder.Has`가 없는 Sprite의 표시를 누락시키지 않게 새 카탈로그 검사로 대체한다.
7. **HUD·효과를 통일한다.** UIPrefabSetup, IconLibrary, RuntimeSprite 및 관련 HUD에서 생성하는 그림을 조사한다. 버튼 상태·선택·비활성·툴팁·한국어 줄바꿈을 유지하면서 스킨과 아이콘을 바꾼다.
8. **씬과 렌더 설정을 전환한다.** SampleScene과 Sandbox를 모두 처리한다. 최초에는 현재 URP에서 Unlit Sprite를 검증하고, 2D Renderer는 필요가 있을 때 전환한다. Pixel Perfect Camera 등 신규 패키지는 현재 Unity 버전 호환 확인 후 추가한다. 2D 화면 전환을 위해 Rigidbody2D나 Physics2D를 일괄 도입할 필요는 없다.

새 작업에서도 Data/Core는 표시 설정 값만 담고 Systems는 자체 상태를 갖지 않는다. 게임 규칙을 비주얼 전환에 맞춰 바꾸지 않는다.

총 예상: **약 7.5~13 작업일**. 방향별 정교한 전투 애니메이션이나 모든 도시 레벨의 독립 그림 제작은 별도 범위다. 1단계의 한 화면 시범이 통과한 다음 전체 자산 변환을 진행한다. 그때까지 기존 3D 자산을 보존해 비교·복구에 사용한다.

## 8. 검증과 종료 조건

- 에셋: 사용 중인 모든 VisualId가 매핑되며, 임시 Sprite·3D fallback이 없다. LICENSE·출처와 편집본 기록이 있다.
- 입력: 셀 중심·경계, 맵 가장자리, 줌·패닝 이후, UI 위 클릭, 배치·호버가 동일한 칸을 가리킨다.
- 전투: 선택→이동→공격→턴 종료, 피격·사망·치유·방어·은신·전향 등 기존 표시 상태가 유지된다. 스탯·경로·피해 계산 결과는 전환 전과 같다.
- 경제: 채집 자원 제거, 벌목 지형 변경, 건설·철거, 도시 성장·성벽·공원, 신전 레벨, 도로 연결·다리 방향을 확인한다.
- 해상: 승선·업그레이드·하선, 6종 선체와 탑승 유닛, 바다/얕은 물 구분을 확인한다.
- 시야: 미탐험 칸의 자원·건물·유닛이 새로 생성되거나 갱신되어도 노출되지 않는다. 기존 은신 규칙을 보존한다.
- 화면: 1280×720, 1920×1080, 넓거나 좁은 종횡비에서 픽셀 번짐·atlas 경계·정렬·한글 잘림·HUD 중첩을 확인한다.
- 성능: 기존 버전과 같은 최대 허용 맵에서 초기 생성·턴 갱신·패닝의 프레임 시간, 메모리, draw call을 비교한다. 타일마다 Update·Animator·Material을 추가하지 않는다.
- 정리: 씬·프리팹·에디터 생성기·Resources 로드의 3D 참조를 먼저 제거한 후 미사용 FBX·재질·모델 CSV를 정리한다. 공용 코드와 폰트는 실제 참조에 따라 판단한다.

구현 시에는 프로젝트 규칙에 따라 Unity CLI로 필요한 검증과 빌드를 실행한다. 이번 문서 작성에는 Unity 실행이 필요하지 않다.

## 9. 바로 착수할 첫 작업 묶음

첫 구현 범위는 **CC0 기본 팩 확보 → 매핑표 작성 → 좌표·입력 어댑터 → 8×8 시범 화면**이다. 무료 팩의 실제 내용을 보기 전에는 모든 항목의 원본 파일명이나 정확한 대체율을 확정하지 않는다. 시범 화면에서 스타일과 클릭 정확도가 확인되면 같은 규격으로 전 자산을 전환한다.
