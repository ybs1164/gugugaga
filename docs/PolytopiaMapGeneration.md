# Polytopia 맵 생성 규칙 요약

출처: [Polytopia Wiki - Map Generation](https://polytopia.fandom.com/wiki/Map_Generation) (Fandom, CC-BY-SA).
아래는 이 프로젝트의 절차적 지형 생성 규칙을 재정비하기 위해 원문을 항목별로 요약/번역한 것이다
(수치는 원문 그대로 인용). 2026-09-23 원문 위키텍스트(Fandom API로 받은 최신판)와 다시 대조해 누락/오역을
바로잡았다 — 원문에 없는 이 프로젝트만의 해석/보강 규칙은 12절에 따로 모았다(원문 내용과 섞지 않는다).

원문 도입부: 모든 게임은 무작위 생성된 정사각형 맵에서 진행되고, 맵은 6가지 크기 × 6가지 물 양 조합이다.
지형은 종족(tribe)마다 다른 비율로 스폰되며, **초기 맵 생성 시 땅은 게임 내 모든 종족에게 대략 균등하게
분배된다**(= 수도 간 간격/영역 크기가 공정해야 한다는 근거).

## 1. 맵 크기

정사각형 그리드, 6종류:

| 크기 | 타일 수 | 변 길이 |
|---|---|---|
| Tiny | 121 | 11x11 |
| Small | 196 | 14x14 |
| Normal | 256 | 16x16 |
| Large | 324 | 18x18 |
| Huge | 400 | 20x20 |
| Massive | 900 | 30x30 |

- Perfection 모드는 항상 Normal.
- Domination 모드는 상대 수에 따라 자동 결정(상대 1명=Tiny, 2명=Small, 3명=Normal, 4명 이상=Large).
- 멀티플레이/크리에이티브는 방장이 직접 선택. Tiny는 최대 9명, 그 외는 최대 16명까지 지원.

## 2. 물 양(습도) 프리셋 — 6종

지형 생성 알고리즘에 "이 맵에 물을 얼마나 배치할지" 가이드를 주는 값. 맵 형태(대륙 모양)와 습도(%)가
세트로 묶여 있다.

| 맵 타입 | 습도(%) | 결과 |
|---|---|---|
| Drylands | 0~10% | 물이 거의 없음(전부 육지). Kickoo/Luxidoor/Aquarion 수도는 예외적으로 물 2칸 + 각 칸에 물고기 |
| Lakes | 25~30% | 중간 습도 → 내륙 호수가 흩어짐. 맵 가장자리에 항상 육지 다리가 생기고, 모든 플레이어는 최소 2개 마을과 육로로 연결 보장 |
| Continents | 40~70% | 크지만 서로 떨어진 대륙. 습도가 높을수록 대륙이 줄고 바다가 넓어짐(Moonrise 업데이트 이전 맵과 가장 비슷) |
| Pangea | 40~60% | 맵 중앙의 큰 대륙 하나 + 외곽 바다 + 가끔 섬 |
| Archipelago | 60~80% | 불규칙하고 불연속적인 땅덩이/작은 섬 사슬, 거의 모든 도시가 해안 |
| Water World | 90~100% | 거의 모든 칸이 물. 마을 1~2개짜리 작은 땅덩이만 존재하며, **도시 자리의 땅은 수동으로 강제 생성**됨 |

## 3. 타일 스폰 비율 (Spawn Rates)

기준값(Luxidoor 종족 기준)은 **도시/마을에 바로 인접한 칸(Inner City)** 과 **인접하지 않은 칸(Outer City)** 에
따라 다르다. 업데이트 2.0.58("Balance Pass 2") 이후로는 지형이 **항상 이 비율대로(가능한 한 정확히)** 생성된다 —
예: Luxidoor는 자기 영역의 48%가 항상 평지. 즉 확률 추첨이 아니라 **목표 개수(쿼터)를 맞추는 방식**이다.

| 분류 | Inner City | Outer City |
|---|---|---|
| Field(평지) 총합 | 48% | 48% |
| ㄴ Fruit(과일) | 18% | 6% |
| ㄴ Crop(작물) | 18% | 6% |
| ㄴ Empty Field(빈 평지) | 12% | 36% |
| Forest(숲) 총합 | 38% | 38% |
| ㄴ Animal(사냥감) | 19% | 6% |
| ㄴ Empty Forest(빈 숲) | 19% | 32% |
| Mountain(산) 총합 | 14% | 14% |
| ㄴ Metal(광물) | 11% | 3% |
| ㄴ Empty Mountain(빈 산) | 3% | 11% |

- 얕은 물(shallow water) 중 50%는 물고기(Fish). 물고기는 종족 국경 안(및 일부 국경 밖)의 깊은 바다에도 생길 수
  있다(국경 확장으로 얻음).
- 자원(Fruit/Crop/Animal/Metal/Fish 등)은 **항상 도시/마을로부터 2칸 이내**에서만 스폰된다 —
  이 규칙 하나로 마을/적 도시 위치를 역추적할 수 있을 정도로 강한 제약.
- Starfish(불가사리)는 도시/마을과 무관하게 물 타일 전역에 흩뿌려짐(별도 규칙, 아래 10절).

## 4. 종족별 스폰 비율 배수 (Modifier)

기준(Luxidoor=1.0x)에 대한 곱연산 배수. 배수 적용 순서가 결과에 영향을 준다:

1. **Mountain 배수를 먼저 적용** → 그 결과가 Forest/Field 비율에도 비례해서 영향을 줌.
2. 그다음 **Forest 배수 적용** → 이제는 Mountain에는 영향 없이 Field에만 영향.
3. **Field는 배수가 없고** 항상 `100% - Mountain% - Forest%`로 나머지 계산.

배수 세트를 CSV로 지정하게 하면 이 구조를 그대로 재현할 수 있다.

## 5. 맵 생성 순서 (전체 파이프라인)

```
1. 수도(Capital) 배치
2. 마을(Village) 배치
3. 지형(Terrain: 산/숲/물) 생성
4. 자원(Resource) 배치
5. 유적(Ruins) / 불가사리(Starfish) 배치
```

원문 표현상 "일반적인 순서"이며 맵 타입마다 변형이 있다(Continents/Pangea는 땅을 먼저 만들고 마을/수도를
나중에 정함 — 7.5절).

**핵심 포인트: (쿼드런트 맵 기준) 수도/마을이 먼저 정해지고, 그다음 지형이 채워지고, 마지막에 자원이 그 지형
위에 얹힌다.** 7차 재정비에서 이 순서로 맞췄다.

## 6. 수도(Capital) 배치 — 쿼드런트(Quadrant) 시스템

- Drylands/Lakes/Archipelago/Waterworld 맵 타입에서 사용(Continents/Pangea는 미사용, 아래 7.4절 참고).
- 인원 수에 따라 맵을 균등한 구역(쿼드런트)으로 분할:
  - 1~4명 → 4구역
  - 5~9명 → 9구역
  - 10~16명 → 16구역
- 각 수도는 맵 생성 맨 처음에 **아직 아무도 배정되지 않은 구역**에 가중 랜덤(weighted randomness)으로 하나씩
  배치 — 플레이어끼리 너무 가깝게 시작하지 않도록 보장하는 공정성(fairness) 규칙.
- 원문은 구역 안에서의 정확한 가중치/가장자리 여백을 밝히지 않는다(이 프로젝트의 해석은 12절).

## 7. 마을(Village) 배치 규칙

마을은 3종류로 나뉜다: **Suburb(근교 마을)**, **Pre-terrain(1차, 지형 생성 전)**,
**Post-terrain(2차, 지형 생성 후)**.

### 7.1 맵 타입별 마을 생성 기능 매트릭스

| 기능 | Drylands | Archipelago | Lakes | Waterworld | Continents/Pangea |
|---|---|---|---|---|---|
| 쿼드런트로 수도 배치 | ✅ | ✅ | ✅ | ✅ | ❌ |
| Suburb | ❌ | ✅ | ✅ | ❌ | ❌ |
| Pre-terrain 마을 | ❌ | ✅ | ✅ | ✅ | ❌ (해당 없음) |
| Post-terrain 마을 | ✅ | ✅ | ✅ | ✅ | ✅ |
| Tiny Island 마을 | ❌ | ❌ | ❌ | ✅ | ✅ |
| Pre-terrain 밀도 계수 | 없음 | 0.3 | 0.3 | 0.1 | 없음 |

### 7.2 Suburb (근교 마을) — Lakes/Archipelago 전용

수도 배치 직후, 그 수도에 딸린 특별한 마을을 근처에 최대 2개까지 추가 배치(0개/1개가 나올 수도 있지만,
큰 맵일수록 1개는 드물고 보통 2개). 수도 근처라는 보장은 없지만 지형 생성 **전에** 배치되므로 보통 수도에서
몇 칸 떨어진 곳에 위치하게 된다.

### 7.3 Pre-terrain 마을(1차 마을) — Archipelago/Lakes/Waterworld

공식:

```
Pre-terrain 마을 수 = (floor(맵 가로/3)^2 - (수도 수 + Suburb 수)) * 밀도 계수
```

- 밀도 계수: Lakes/Archipelago = 0.3, Waterworld = 0.1. `맵 가로/3`은 제곱하기 전에 내림한다.
- 배치 제약: 다른 마을로부터 2칸 떨어져야 하고(= 바로 인접 금지), 맵 가장자리로부터 최소 1칸.

### 7.4 Post-terrain 마을(2차 마을)

지형(산/숲/물)이 전부 채워진 **이후** 추가로 배치. 이 시점부터는 "몇 개를 배치할지"를 정해두지
않고, **더 이상 넣을 자리가 없을 때까지** 계속 무작위로 채워 넣는다. 제약:

- 맵 가장자리로부터 2칸 이내에 놓이면 안 됨(원문에 "가장자리에서 3칸"이라는 조건도 별도로 적혀 있어 모호함 —
  이 프로젝트는 CSV EdgeMargin=2로 해석).
- 다른 마을로부터 2칸 이내에 놓이면 안 됨.
- Drylands 맵의 모든 마을은 전부 이 방식(Post-terrain)으로만 생성됨.

### 7.5 Continents / Pangea — 별도 프로세스

이 두 맵 타입은 Suburb/Pre-terrain 마을 자체가 없고, 쿼드런트도 쓰지 않는다(대신 아래 순서):

**Pangea**:
1. 맵 정중앙 한 점을 시작점으로 육지 덩어리를 퍼뜨림 — 육지/물 비율은 습도로 정해지며 Pangea는 약 절반이 물.
2. 쿼드런트 없이, 육지 위에 마을을 한 번에 하나씩(서로 최소 2칸 간격) 더 이상 자리가 없을 때까지 배치.
3. 이미 배치된 마을 중 일부를 **수도로 전환** — 이때 (a) 수도끼리 최대한 멀리 떨어지도록, (b) 가능하면
   해안(물 인접) 타일을 우선하도록 두 기준으로 선택 → 그래서 수도가 거의 항상 해안에 위치하게 됨.
4. 본토 마을/수도 배치가 끝난 뒤, 맵 크기에 따라 육지와 연결되지 않은 "외딴 섬 마을"을 별도로 추가(8절).

**Continents**:
1. 노이즈 기반으로 여러 개의 개별 대륙(landmass)을 생성 — 대륙 개수는 플레이어 수/습도/맵 크기에 좌우,
   약 절반이 물. 각 대륙은 30~200타일 크기, 대륙끼리 최소 1칸 간격(예: 196칸 맵 + 2명 + 물 절반이면 대륙당
   약 50칸). 1칸 폭 얕은 물 줄기("강")가 자주 생긴다.
2. 대륙마다 한 번에 하나씩 마을 배치(서로 2칸 간격), **모든 대륙에 최소 1개 마을 보장**.
3. Pangea처럼 **플레이어당 마을 1개를 수도로 전환** — 공간이 허락하면 수도끼리 서로 다른 대륙에 배치.

## 8. 외딴 섬 마을 (Tiny Island Villages)

Continents/Pangea 전용. 본토와 육로로 연결되지 않은 채 바다 한가운데 물로만 둘러싸인 마을을
맵 크기에 비례해 고정 개수만큼 추가:

| 맵 크기 | 타일 수 | 외딴 섬 마을 수 |
|---|---|---|
| Tiny | 121 | 0 |
| Small | 196 | 1 |
| Normal | 256 | 2 |
| Large | 324 | 3 |
| Huge | 400 | 4 |
| Massive | 900 | 9 |

(참고: Aquarion 종족은 깊은 바다 유적을 점령하면 항상 레벨 3 도시가 되고 주변에 물고기/수중작물
자원이 새로 생기는 특수 규칙이 있음 — 이 프로젝트 범위에서는 참고만 하고 반영하지 않는다.)

## 9. 유적(Ruins)

- 마을/자원/등대 배치가 끝난 **뒤에** 무작위로 배치.
- 산/숲/평지/깊은 바다 위에 스폰 가능.
- 다른 유적이나 마을과 바로 인접할 수 없음.
- Lakes 맵은 유적의 최대 1/3까지만 물 위에 스폰 허용.

| 맵 크기 | 타일 수 | 유적 수 |
|---|---|---|
| Tiny | 121 | 4 |
| Small | 196 | 5 |
| Normal | 256 | 7 |
| Large | 324 | 9 |
| Huge | 400 | 11 |
| Massive | 900 | 23 |

## 10. 불가사리 (Starfish)

- 물 타일 약 **25칸당 1개** 꼴로 스폰(마을/도시 인접 여부와 무관).
- 얕은 바다/깊은 바다 모두 가능.
- 다른 불가사리, 등대, 도시와 바로 인접 불가.

## 11. 이 프로젝트에 적용할 요약 시사점 (6차 재정비 시점 작성)

1. **생성 순서 재정비**: "지형 먼저 → 그 위에 세부 자원/장식 배치" 순서를 유지하되, Polytopia처럼
   "수도/마을(스폰 포인트) 먼저 확정 → 그 주변부터 지형 채우기" 순서로 바꾸는 편이 더 원작에 가깝고
   플레이어 공정성도 챙길 수 있다.
2. **쿼드런트 기반 공정 배치**: 기존 Voronoi 랜덤 시드점 대신, 플레이어 수에 따라 그리드를 균등
   구역으로 나누고 구역당 하나씩 시작 지점을 배정하는 방식이 다인원 대전에서 더 공정하다.
3. **"도시/마을 인접 2칸 이내에서만 자원 스폰"** 규칙은 지금 프로젝트의 "인접 배제(ExcludeAdjacent)"
   규칙과 반대 방향(인접 허용 범위 지정)이라 새로운 CSV 필드로 추가할 필요가 있다.
4. **Inner/Outer 이중 비율 구조**: 같은 타일 타입이라도 스폰 지점(마을) 근접도에 따라 확률이 달라지는
   구조 — 지금 CSV는 바이옴당 균일한 Weight 하나뿐이라 Inner/Outer 두 값으로 분리할 필요가 있다.
5. **최소/최대 개수+간격 제약의 다양성**: 마을처럼 "다른 것과 최소 N칸", "가장자리에서 최소 N칸" 같은
   거리 기반 제약이 반복되므로, 기존 "인접 타일 배제"보다 일반화된 "최소 거리 제약"으로 확장할 필요가
   있다.
6. **맵 크기별 스케일링 표**: 유적/외딴섬 마을처럼 맵 크기에 비례해 개수를 정하는 lookup table 방식은
   지금 프로젝트의 고정 MinCount보다 유연하다 — "맵 크기 대비 비율"이나 "타일 수당 개수" 방식 도입을
   고려할 만하다.

## 12. 원문에 없는 이 프로젝트의 보강 규칙 (8차 재정비)

원문 규칙만으로는 아래 문제가 생겨서(1~4), 원문의 취지("땅은 모든 종족에게 대략 균등", "Waterworld도 도시
자리의 땅은 강제로 생성", "마을은 서로 2칸 간격")를 해치지 않는 선에서 규칙을 보강했다.

| 문제 | 원인 | 보강 규칙 |
|---|---|---|
| 1. 수도 간 간격이 들쭉날쭉 | 구역 안 아무 칸이나 균등 랜덤, 빈 구역도 무작위 선택 | 쿼드런트 수는 원문대로 4/9/16. 구역 **중심부**(구역 한 변의 1/4 반경)에서만 뽑고, 구역 경계 칸은 제외. 바이옴 수 < 구역 수면 **서로 가장 먼 구역**부터 채운다(2명=대각선). Pangea/Continents는 원문대로 땅을 먼저 만든 뒤 여러 번 시도해 **최소 쌍 거리가 가장 큰** 수도 조합을 채택 |
| 2. 수도가 1칸 섬에 생김 | 수도 칸 하나만 육지로 보장 | 쿼드런트 맵은 수도 **3x3 전체를 육지로 강제**(물 비율보다 우선). Pangea/Continents는 **육지 덩어리 9칸 이상**인 칸만 수도 후보 |
| 3. 수도가 맵 벽(가장자리)에 붙음 | 가장자리 여백 규칙 없음 | 수도는 가장자리로부터 **최소 2칸**(= 3x3 영역이 맵 안에 들어가고 한 칸 여유) |
| 4. 마을끼리 붙어서 연속 생성 | Suburb에 간격 검사 없음, Post-terrain 마을의 최소 거리가 바이옴 영역 안에서만 검사됨, 외딴 섬 마을도 검사 없음 | 수도/마을(Suburb·Pre-terrain·Post-terrain·외딴 섬)을 전부 "도시"로 묶어 **맵 전체 기준으로 서로 최소 2칸**(체비쇼프 거리 ≥ 2, 인접 금지). CSV MinDistance가 더 크면 그 값 |

### 12.1 숲/산 레이어 (3절 Spawn Rates 반영)

- 바이옴 CSV에 `MountainRate`/`ForestRate` 컬럼(종족 배수와 같은 의미의 배수, 1.0 = Luxidoor 기준값)을 추가했다.
  비워두면 0 = 숲/산 레이어 없음(기존 CSV와 호환).
- 각 바이옴 영역의 육지 칸(수도/마을 칸 제외) 중 **산 = 14% × MountainRate**를 먼저 정하고, 그 결과에
  비례해 **숲 = 38% × (100%−산%)/86% × ForestRate**를 정한다(4절 "산 배수 먼저 → 숲 배수 → 나머지 평지").
  Balance Pass 2처럼 확률 추첨이 아니라 **쿼터(목표 개수)를 정확히 채운다**.
- 어느 칸이 산/숲이 될지는 노이즈 순위로 정해서 한 칸씩 흩뿌려지지 않고 산맥/숲 덩어리로 뭉친다.
- 산/숲 칸의 TileTypeId는 `Mountain`/`Forest`(TerrainType은 Land 그대로 — 이동 판정은 이번 범위에서 변경 없음).
  나머지 육지 칸(CSV 타일: Grass/Sand/Rock/Snow…)이 평지(Field) 역할이다.
