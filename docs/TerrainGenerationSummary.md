# 절차적 지형 생성 요약

## 필수 구성요소 체크리스트

절차적 지형 생성 알고리즘이 갖춰야 할 요소와, 이 프로젝트가 각각을 어디서 채우는지.

| 요소 | 역할 | 이 프로젝트의 구현 |
|---|---|---|
| 시드/재현성 | 같은 입력이면 항상 같은 결과 | `System.Random(seed)` 하나로 파이프라인 전체 고정 |
| 노이즈 함수 | 유기적(랜덤이지만 매끄러운) 패턴 생성 | `NoiseSystem.Sample`(프랙탈 Perlin, 0~1 정규화, `seedOffset`으로 독립 필드) |
| 입력 규칙 | "무엇을 어떻게 생성할지" 정의 | 바이옴 CSV(타일 규칙 + 구조물 규칙) |
| 매크로 구조(지역 분할) | 맵을 큰 덩어리로 먼저 나눔 | 쿼드런트 앵커(수도) + Voronoi 배정, Suburb/Pre-terrain 마을 사전 배치, 랜드마스 마스크(대륙/호수/섬 모양) |
| 마이크로 구조(제약) | 칸 단위로 규칙 위반 방지 | 최소 거리, 가장자리 여백, 인접 배제 |
| 확률적 선택 | 같은 규칙에서도 다양한 결과 | Inner/Outer 가중치 × 노이즈로 가중 랜덤 선택 |
| 밀도/개수 제어 | 맵 크기·영역 크기에 맞는 양 조절 | 고정 최소 개수 vs 영역 크기 비례 개수 중 큰 값 채택 |
| 후처리(장식 레이어) | 지형 위에 얹는 요소 | 구조물 생성(수도/자원/유적/마을) — 별도 패스, 이동 판정엔 무관 |
| 출력 | 생성 결과를 실제 게임 데이터로 기록 | `GridWorld`에 지형/타일/구조물 값 기록 → View가 읽어 렌더링 |
| 검증 | 알고리즘이 규칙대로 동작하는지 확인 | CLI 배치 자동 테스트(제약 준수/비율/재현성) |

## 1. 입력
- 바이옴 CSV(`BiomeCsvRow`): 노이즈 설정 + 타일 규칙(`Tiles`) + 구조물 규칙(`Structures`).
- 타일 규칙: 타입(육지/물), Inner/Outer 확률, 최소 개수, 최소 거리, 가장자리 여백, 인접 배제.
- 구조물 규칙: 놓일 수 있는 타일 타입, 확률, 최소 개수, 수도로부터 최대 거리, 물 배치 비율 상한, 무제한 채우기 여부, 인접 배제.

생성 순서는 **수도 → 마을 → 지형 → 구조물**(Polytopia와 동일한 순서) — 수도/마을 위치를 먼저 정하고,
지형 생성이 그 위치를 반드시 육지로 보장한 뒤 채운다.

## 2. 수도/마을 위치 계획 (지형 생성 전)
1. 바이옴 수만큼 맵을 구역(1~4개=4, 5~9개=9, 10~16개=16)으로 나눠 구역마다 수도 앵커 하나씩 배정(쿼드런트).
   구역이 남으면 서로 가장 먼 구역부터 채우고, 구역 안에서도 중심부만 후보로 삼으며, 가장자리 2칸 이상 +
   수도끼리 3칸 이상 떨어뜨린다(8차 재정비 — 간격 고르게, 벽에 붙지 않게). Pangea/Continents는 이 단계를
   건너뛰고 땅을 먼저 만든 뒤 고른다(4절).
2. Suburb 마을(Lakes/Archipelago만): 수도마다 반경 3칸 안에 0~2개, 다른 수도/마을과 인접 금지.
3. Pre-terrain 마을(Lakes/Archipelago/Waterworld만): 맵 크기 기반 공식으로 개수를 정해, 다른 마을/수도와
   최소 거리·가장자리 여백을 지키며 배치.
4. 수도 3x3 + Suburb + Pre-terrain 마을 위치 전부를 "반드시 육지가 되어야 할 칸"으로 지형 생성에 넘긴다
   (목표 물 비율보다 우선 — 수도가 1칸 섬에 생기지 않음).

## 3. 타일 생성 — 자유 배치 (Drylands 포함 기본 경로)
1. 계획 단계에서 정한 수도 앵커로 모든 칸을 가장 가까운 앵커의 바이옴에 배정(Voronoi).
2. 습도 배율을 물 타일 확률/개수에만 적용.
3. 바이옴별 최소 개수를 먼저 채움(거리·인접 제약 지키며).
4. 남은 칸을 Inner/Outer 확률 × 노이즈로 가중 랜덤 채움.
5. 수도 3x3/마을 칸을 강제로 그 바이옴의 육지 타일로 덮어써 육지를 보장.
6. 숲/산 레이어: 바이옴 CSV `MountainRate`/`ForestRate`가 있으면, 수도/마을 칸을 뺀 육지 중 산 14%×배수,
   숲 38%×(100%−산%)/86%×배수를 정확히 쿼터로 `Mountain`/`Forest` 타일로 바꿈(노이즈 순위로 뭉치게).

## 4. 타일 생성 — 랜드마스 마스크 (Pangea/Lakes/Continents/Archipelago/Waterworld)
개별 타일 확률만으로는 대륙/호수 같은 공간적 모양이 안 나와서, 모양을 먼저 마스크로 확정한 뒤 위 3~4단계를 얹는다.
1. 중심점(프리셋마다 개수 다름) 기준 방사형 감쇠 + 노이즈로 칸마다 점수 매기고, 수도/마을 칸엔 큰
   보너스를 더해 점수 상위 칸(목표 물 비율만큼)을 육지로 확정 — 수도/마을이 항상 육지에 포함되게 함.
2. 그래도 물로 남았다면 가장 가까운 육지로 이동(안전망).
3. 물로 확정된 칸은 거리 제약 없이 바로 물 타일로 채움(바다가 끊기지 않게).
4. Pangea/Continents는 이 시점에 수도를 고른다 — 가장자리 2칸 이상 + 9칸 이상 육지 덩어리 위에서,
   수도끼리 최대한 멀게(farthest-point를 여러 번 시도해 최소 쌍 거리가 가장 큰 조합), 해안 선호,
   Continents는 가능하면 서로 다른 대륙.
5. 육지로 확정된 칸만 위 자유 배치의 3~4단계로 채우고, 마지막에 숲/산 레이어(3절 6단계)를 적용.

| 프리셋 | 중심점 | 특징 |
|---|---|---|
| Pangea | 1개(중앙) | 중앙 대륙 + 외곽 바다 |
| Lakes | 0개(노이즈만) | 흩어진 호수, 테두리는 항상 육지 |
| Continents | 바이옴 수만큼 | 대륙 여러 개로 분리 |
| Archipelago | 바이옴 수만큼(노이즈 비중↑) | 흩어진 작은 섬 |
| Waterworld | 바이옴 수만큼 | 거의 전부 물, 수도/마을 주변만 육지 |

## 5. 구조물 생성 (타일 생성 이후)
1. 수도 앵커마다 수도 구조물 배치, Suburb/Pre-terrain 마을 위치마다 마을 구조물 배치(둘 다 이미
   지형 생성이 육지로 보장한 칸).
2. 바이옴별 구조물 규칙마다 목표 개수 계산 후, 조건(허용 타일/거리/인접) 맞는 빈 칸에 확률 비례로 배치
   (자원/유적/불가사리/Post-terrain 마을 — 위 1단계가 채운 칸은 자동으로 후보에서 제외됨). 거리 검사는 맵 전체
   기준이고, 수도/모든 마을은 서로 인접 금지(체비쇼프 2 이상).
3. 외딴 섬 마을(Pangea/Continents 전용): 사방이 물로 막힌 고립 칸을 육지로 바꿔 배치(맵 크기별 개수 고정).

## 6. Sandbox UI
- 맵 크기, 습도(=랜드마스 모드 + 물 비율) 버튼으로 선택 → "지형 생성" 클릭 시 수도/마을 계획 → 타일
  생성 → 구조물 생성 → 화면 갱신 순으로 실행.

## 7. 검증
- Unity CLI 배치모드 자동 테스트로 제약 준수, 개수/비율, 시드 재현성, 프리셋별 모양 특징, 수도/마을
  위치의 육지 보장을 PASS/FAIL로 확인.
